## Findings

1. **A database outage signs people out.** The database world's eight `fail`
   operations, at 5.1 to 7.8 s, are all `rejected: HTTP 401 Authentication
   required`, from a driver whose session was valid throughout. `createContext`
   (`api/context.ts`) catches every error from `authenticateRequest`, including
   a database it cannot reach, and treats the request as signed out. The web
   app takes UNAUTHORIZED as "sign in required": pages show sign-in prompts, and
   if it asks who is signed in during the outage, `auth.me` answers 401 too and
   the auth guard sends the user to the login page. A
   database blip should be a server error the client can retry, not a sign-out.
   The history is right to call these `fail`, since nothing was applied, so no
   oracle judged it. Not yet fixed; it needs an oracle first.
2. **Still open: the audit writer's deadlock** (OBS-GATE-001, finding 2). Not
   seen in these runs.
