**The worker-restart world passed, but not for the predicted reason** (`489e`).
The prediction was that SIGTERM lets worker-a finish its import within its
5 s grace or return it to the queue, because "`docker stop` waits 10 s before
SIGKILL". What happened:

- worker-a logged `SIGTERM: finishing the current job (up to 5 s), then exiting`
  at 3.7 s and was running again under a new id at 5.6 s. It had not finished
  its job: at the drain, 13.8 s, all six clients were following job 1, still
  `running`.
- Job 1 ended `succeeded` only after the drain (`sync_jobs.settle`: 8 rows, the
  seed's 6 plus 2 new, both succeeded), which is why the world passed. The
  driver recorded a single `ok` in 13.8 s, against 21 in the pause world.

Reproduced directly on a scratch stack of the same images: with worker-a holding
job 2, `docker compose stop worker-a` took 1.5 s, the container exited with code
137 (SIGKILL, not OOM), and job 2 was still `running` under the dead worker's
lease. The container's `Config.StopTimeout` is 1. So is every container on this
host, including a plain `docker create alpine`, and `daemon.json` sets nothing,
so it is this Docker Desktop's default. On this host, `docker stop`, and with it
`proc.restart`, sends SIGKILL one second after SIGTERM.

## Findings

1. **A stopped worker cannot finish or hand back its job on this host.** Ontos's
   compose files (`compose.yaml` and `gate/compose.gate.yaml`) set no
   `stop_grace_period`, so the worker gets whatever the Docker host defaults to:
   1 s here, 10 s on a stock Engine. Here the 5 s grace never runs; the job
   waits for its lease to lapse (up to 15 s) and is imported again from the
   start by another worker. The lease worked as the fallback it is, but the
   designed path never ran, and whether it runs depends on the machine. No
   oracle judges how a job was recovered, only that it settled within 30 s,
   which is why the world passed. Not yet fixed; the next pre-registration adds
   an oracle for it first.
2. **The audit writer's deadlock still reproduces** (OBS-GATE-001, finding 2).
   It appeared while sizing the bulk fixture on a scratch stack: two 2000-row
   imports finishing together on two workers, one failing its first attempt on
   `insert into audit_log`, then succeeding on retry. The queue now absorbs it;
   the writer is unchanged.
3. **The pause world's margin at the start is thin.** The first imports were
   queued at 1.9 s and worker-a was frozen at 3.0 s, so its claim fell in a
   1.1 s window. A slower sign-in would freeze an idle worker, and the world
   would pass without testing a lease, as `4c2f` did.

## For the PRO-THESIS side

- `proc.restart`'s grace before SIGKILL is the Docker host's default stop
  timeout (1 s on this Docker Desktop), and the world file does not record it.
  The same world can mean "graceful restart" on one host and "kill" on another.
- The lock records the checker's digest, and Go stamps the commit into the
  binary (`vcs.revision`), so every commit gives `bin/oracle-sync-jobs.exe` a
  new digest and `thesis run` warns that the program deciding the verdict
  changed. It did not: `git log 07dc87b..e3efc36 -- gate/cmd/oracle-sync-jobs`
  is empty.
