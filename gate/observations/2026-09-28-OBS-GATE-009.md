# OBS-GATE-009: pre-registrations 8 and 9 recounted from kept bundles

2026-09-28 (UTC). Tool: `thesis` v0.1.0-phase0, lock `sha256:dbf08316…`. Since
#11, CI keeps each Gate run's bundles as the artifact `gate-runs-<run>-<attempt>`
for 30 days. This recounts what OBS-GATE-005 and -006 could not: whether each
run of the signed-in-clients and Ontology API worlds counts, by the rules the
pre-registrations set, and what it showed.

It covers every kept artifact from `36371049416` (02:45) to `36378913706`
(04:43): 10 Gate runs of 11 worlds, on master and on the branches of #10 to #14.
[`recount.ps1`](2026-09-28-OBS-GATE-009/recount.ps1) downloaded and tallied them;
its output is [`recount.txt`](2026-09-28-OBS-GATE-009/recount.txt). Nothing was
re-run.

## How a run was counted

- **Answered during the outage.** A completion the driver recorded inside the
  fault's realized window (`world.thesis`, `start_ms..end_ms`), whose error
  names `HTTP 503` or `HTTP 401`.
- **Pre-registration 8:** a run counts only if at least one request was
  answered during the outage.
- **Pre-registration 9:**
  - A run counts only if `api.read_your_writes` judged at least one read; its
    explanation says how many.
  - The database world counts for the outage by the same rule as
    pre-registration 8.

## Findings

1. **Pre-registration 9 holds** in all 27 kept runs of its three worlds. Every
   run counts, no read was stale, and the API answered 503, never 401, while
   the database was down.
2. **Pre-registration 8 holds** in the 6 of its 9 runs that count. Three missed,
   none in a row.
3. **The audit writer's deadlock is common under concurrent submissions,** at
   3 to 20 HTTP 500s a run, and was absent in the one run of the fix (#14,
   since merged).
4. **A vacuous world recurs** under the worker restart, as under the fault-free
   API world. OBS-GATE-007's first item for decision covers both.
